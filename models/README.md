# Models

This folder contains:

- the four optimization models that run on top of a `SimulationResult`
- model-specific plot wrappers
- a shared visualization utility layer in `plot_utils.py`

The goal is for notebooks from different scenarios to reuse exactly the same API.

## Structure

- `model1_max_routes.py`
  Maximizes the number of enabled routes under a key-budget constraint.
- `model2_min_keys.py`
  Minimizes the number of keys required to achieve a connectivity target.
- `model3_min_keys_full_connectivity.py`
  Minimizes the number of keys needed to guarantee at least one route per pair.
- `model4_max_connectivity_under_budget.py`
  Maximizes pairwise connectivity under a key-budget constraint.
- `plot_utils.py`
  Generic builders and plots based on `traces`, independent of the model.

## Input Requirement

All four models receive a `result` generated by `SimulationPipeline.run(...)` or `SimulationPipeline.run_loaded(...)`.

Example:

```python
from modules.security.models import SecurityModelType
from pipelines.routing import CGRYenRouting
from pipelines.simulation import SimulationPipeline

pipeline = SimulationPipeline()

result = pipeline.run(
    cp_path="scenarios/basic/contact_plan.json",
    topology_path="scenarios/basic/topology.json",
    security_models=tuple(SecurityModelType),
    curr_time=0,
    routing_algorithm=CGRYenRouting(max_routes=3),
    num_routes=3,
)
```

## Shared Output Contract

All `solve_for_security_model(...)` functions return:

```python
(traces, df)
```

Where:

- `df` is the traditional sweep-summary `DataFrame`
- `traces` is a tuple aligned row by row with `df`
- when a sweep point has no feasible solution, the corresponding position in `traces` is `None`

This makes it possible to move from an aggregate curve back to the exact solution that produced it.

## What a Trace Contains

Each trace is a `RouteActivationSelection` and summarizes one concrete optimal solution:

- `selected_pairs`
- `selected_route_ids`
- `selected_key_scopes`
- `routes`
- `keys`

Each element of `routes` includes:

- `node_path`
- `network_path`
- `boundary_crossings`
- `gateway_nodes`
- `contacts`
- `operations`

Each element of `keys` includes:

- `scope`
- `route_ids`
- `pair_ids`
- `operation_ids`

In other words, a trace lets you recover the chosen keys, chosen routes, used contacts, and cross-network crossings.

## Model 1

File: `model1_max_routes.py`

Objective:

- maximize `selected_routes`
- under a maximum active-key budget

Signature:

```python
from models.model1_max_routes import solve_for_security_model

traces, df = solve_for_security_model(result, SecurityModelType.EDGE_TO_EDGE)
```

`df` columns:

- `max_keys`
- `selected_routes`
- `selected_pairs`
- `selected_keys`
- `connectivity_pct`
- `model`

Typical notebook usage:

```python
df_m1 = pd.DataFrame()
traces_m1 = {}

for sec_model in SecurityModelType:
    sec_traces, sec_df = solve_for_security_model(result, sec_model)
    traces_m1[sec_model.name] = dict(zip(sec_df["max_keys"], sec_traces))
    df_m1 = pd.concat([df_m1, sec_df], ignore_index=True)
```

## Model 3

File: `model3_min_keys_full_connectivity.py`

Objective:

- minimize `selected_keys`
- while guaranteeing at least one route for every ordered pair

Signature:

```python
from models.model3_min_keys_full_connectivity import solve_for_security_model

traces, df = solve_for_security_model(result, SecurityModelType.EDGE_TO_EDGE)
```

`df` columns:

- `target_connectivity_pct`
- `required_pairs`
- `selected_pairs`
- `selected_routes`
- `selected_keys`
- `achieved_connectivity_pct`
- `model`

This model has a single sweep point, so the usual pattern is to store one trace per model:

```python
df_m3 = pd.DataFrame()
traces_m3 = {}

for sec_model in SecurityModelType:
    sec_traces, sec_df = solve_for_security_model(result, sec_model)
    traces_m3[sec_model.name] = sec_traces[0] if sec_traces else None
    df_m3 = pd.concat([df_m3, sec_df], ignore_index=True)
```

## Model 4

File: `model4_max_connectivity_under_budget.py`

Objective:

- maximize `selected_pairs`
- under a maximum active-key budget
- break ties by minimizing `selected_keys` and then maximizing `selected_routes`

Signature:

```python

traces, df = solve_for_security_model(result, SecurityModelType.EDGE_TO_EDGE)
```

`df` columns:

- `max_keys`
- `selected_pairs`
- `selected_routes`
- `selected_keys`
- `achieved_connectivity_pct`
- `model`

Typical notebook usage:

```python
df_m4 = pd.DataFrame()
```

## Model-Specific Plots

The recommended approach is to start with the wrappers exposed by each model file and drop down to `plot_utils.py` only when you need something more custom.

### Model 1

File: `model1_max_routes.py`

- `plot_selected_routes_vs_keys(df, normalize=False, ...)`
- `plot_budget_key_scope_heatmap(traces_by_budget, ...)`
- `plot_budget_contact_usage_heatmap(traces_by_budget, ...)`
- `plot_budget_gateway_usage_heatmap(traces_by_budget, ...)`
- `plot_budget_network_crossing_heatmap(traces_by_budget, ...)`

Example:

```python
from models.model1_max_routes import (
    plot_budget_contact_usage_heatmap,
    plot_budget_key_scope_heatmap,
    plot_selected_routes_vs_keys,

plot_selected_routes_vs_keys(df_m1)
plot_budget_key_scope_heatmap(traces_m1["EDGE_TO_EDGE"])
```

### Model 2

File: `model2_min_keys.py`

- `plot_selected_keys_vs_connectivity(df, normalize_y=True, ...)`
- `plot_connectivity_pair_coverage_heatmap(traces_by_connectivity, all_pairs=..., ...)`
- `plot_connectivity_key_scope_heatmap(traces_by_connectivity, ...)`
- `plot_connectivity_contact_usage_heatmap(traces_by_connectivity, ...)`
- `plot_connectivity_network_crossing_heatmap(traces_by_connectivity, ...)`

Example:

```python
from models.model2_min_keys import (
    plot_connectivity_pair_coverage_heatmap,
    plot_connectivity_key_scope_heatmap,
    plot_selected_keys_vs_connectivity,
```

## Recommended Notebook Pattern

1. Run `SimulationPipeline`
2. Solve the models with `solve_for_security_model(...)`
3. Store `df_m1`, `df_m2`, `df_m3`
4. Store `traces_m1`, `traces_m2`, `traces_m3`
5. Use model-specific wrappers for the most common plots
6. Use `plot_utils.py` when you need to compose new visualizations

## When to Use `plot_utils.py` Directly

Use it directly when you want to:

- compare different scenarios with the same type of heatmap
- build a plot that is not covered by the wrappers
- transform traces into `DataFrame`s before exporting or analyzing them in pandas

Example:

```python
from models.plot_utils import build_contact_usage_data

contact_df = build_contact_usage_data(
    traces_m1["EDGE_TO_EDGE"],
    sweep_label="max_keys",
)
```

## Note About `None` in Traces

In `model1` and `model2`, some sweep points may have no feasible solution. In that case:

- the row still exists in `df`
- the corresponding position in `traces` is `None`

The shared plotters automatically ignore those points when working from `traces`.
